# M2.2：Windows 选词翻译

> 历史实现：用户实测多个程序不提供选区接口或超时，且要求无需选择文字。本模式保留为可选项，默认已改为 [指针取词与浮窗](M2_POINTER_LOOKUP.md)，不能将本页视为原生验收通过。

## 前置验收与本轮边界

用户明确反馈上一项（Windows 主题与全局唤起/隐藏快捷键）通过，因此进入选词翻译。本轮只实现这一项；区域截图 OCR、托盘尚未开始。上一项通过来自用户原生验收反馈，不是 agent 在 Windows 执行的日志。

新增链路：在其他程序选中文字 → 按 `Ctrl+Alt+T` → 后台读取选区 → 唤起工作台并调用当前文本翻译配置 → 结果可复制/保存生词/复习。沿用现有模型、错误处理、取消、词库和复习逻辑，没有另外的模型后台或固定结果。

## 使用和行为

- “外观与快捷键”中单独修改/禁用选词组合。默认唤起/隐藏 `Ctrl+Alt+W`，选词 `Ctrl+Alt+T`，不能重复；注册冲突或保存失败会保留原有两组绑定。支持两组互换。
- 旧 `desktop.json` 自动兼容。如果旧的唤起键已是 `Ctrl+Alt+T`，保留它，先禁用新选词键，用户改成不重复的组合后再开启。启动时选词键占用不应禁用可用的唤起键，状态栏会提示。
- 取词前不抢走目标窗口焦点。取得选区后才激活工作台，清空上次上下文，按“翻译”模式处理。不会把上一句上下文混入新选区。
- 快捷键意味着将本次选中文字发送到当前模型服务。没有可用翻译配置时先提示设置，不读取选区或发请求。
- 本轮只使用 Windows **UI Automation TextPattern.GetSelection**；不读取整个文档、不自动 Ctrl+C、不写剪贴板。不支持该接口的控件会失败并提供手动粘贴入口，不把旧剪贴板误当新选区。
- 未选中、密码输入、控件不支持、前台变化、超时、辅助组件不可用分别提示。失败时不发送模型请求，也不保存旧结果。收到文本前取消或切换前台同样不会继续翻译。
- 取词等待时可按唤起快捷键回到主窗口；前台变化会中止取词，或点击取消。模型请求期间取消继续沿用原请求取消逻辑。
- 手动回退：在目标应用复制 → 回 WordLoom 点“粘贴剪贴板文本” → 点击“开始处理”。粘贴本身不发请求，清除旧上下文和可保存状态。
- 首版最多 20000 字符；多选区以换行连接。图片、扫描 PDF、画布等不提供文本选区时会提示失败，OCR 属于下一项。

## Windows 实现与依赖

`platforms/selection.py` 为 Windows 适配；`resources/read_selection.ps1` 使用 Windows PowerShell 自带 .NET UIAutomationClient/UIAutomationTypes，在隐藏的独立 MTA 进程中读取当前焦点控件的选区。辅助进程禁用 profile，不执行网络调用，选区只通过内存管道传回；主应用不记录选区到日志。失败只返回固定错误代码。

辅助进程设 5 秒截止时间；工作线程轮询取消/前台窗口及进程状态，超时、取消、退出会结束辅助进程。UI 的 6 秒总时限兜底。使用目标 HWND 和 PID 检查前台变化，并由辅助进程检查焦点控件属于该窗口。所有选区数据先通过类型、长度和空值校验。

没有新增 Python 包依赖。不需要管理员权限；访问高权限程序或某些不支持无障碍接口的程序可能失败，届时手动复制粘贴。缺少 Windows PowerShell/.NET UI Automation 或被本机策略禁止执行时给出失败，不自动安装系统组件或提权。

依据：[Microsoft TextPattern.GetSelection](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.textpattern.getselection)、[UI Automation 线程说明](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading)。子进程隔离也允许终止目标 provider 卡住的同步调用。

## 已执行验证

`validation/selection/results.json`（本地生成，不提交日志）记录：

- **55 项核心测试执行通过**。HTTP 测试类的 6 个用例仍因 agent 套接字权限受限而跳过，不计为通过。
- **12 项界面测试执行通过**，另 1 项真实 HTTP+UI 联合测试环境跳过；offscreen 启动通过。
- 新增覆盖双键冲突/修改事务/互换/旧配置兼容；取词结果校验；真实辅助子进程的管道、超时、取消和焦点变化终止。这里的辅助子进程运行受控测试代码，**不是 Windows UI Automation**。
- Qt 闭环测试从选词快捷键回调开始，接到测试适配器返回文本，使用真实 Client 配合内存 HTTP 边界完成翻译、收藏和复习；验证剪贴板保持原内容、旧上下文清除、失败后可粘贴，以及取消/前台变化不会调用模型。

Windows PowerShell/UI Automation 和具体程序兼容性 **本轮尚未原生验收**；不存在“WSL 测试即 Windows 通过”的结论。macOS 只复用业务逻辑，选区读取和原生验证尚未实现，界面明确不可用。

## Windows 更新与验收

退出旧 WordLoom，在已有 Windows Git 仓库中：

```powershell
git pull --ff-only
.\.venv-win\Scripts\python.exe -m wordloom
```

本轮没有新增 Python 依赖；此前 editable 安装直接使用更新源码。原生自动测试与取词诊断：

```powershell
.\.venv-win\Scripts\python.exe scripts\validate.py --native-hotkeys --output validation\windows-selection
.\.venv-win\Scripts\python.exe scripts\check_selection.py --delay 5
```

第二个命令给出 5 秒切换到目标程序选择文字，只输出读取字符数，不输出原文、不调用模型。该命令是交互验收，不加入无人值守的自动测试。实际 UIA 不支持时记录错误码和应用版本。

| 验收项 | 操作/预期 | 状态 |
|---|---|---|
| 文本编辑器闭环 | 在记事本选中文本，按 Ctrl+Alt+T；选区出现在 WordLoom 并真实翻译；收藏/复习/重启持久化正常 | 待 Windows 验证 |
| 浏览器兼容 | 在 Edge/Chrome 的网页正文选中单词、中文或多行文本；成功时只发送选区，失败时明确提示手动粘贴。记录浏览器版本及页面类型 | 待验证 |
| 剪贴板保护 | 先复制一段对照文字，再选择另一段并触发选词；翻译完成后粘贴应仍为对照文字。图片/文件剪贴板同样不应被改变 | 待验证 |
| 无选区/不支持 | 没有选区或不支持 UIA 的控件触发，不能翻译旧输入/旧剪贴板；手动复制粘贴后可处理 | 待验证 |
| 权限/密码 | 受保护或高权限目标应拒绝或提示失败，不自动提权或发送旧文本 | 待验证 |
| 焦点/取消 | 在辅助读取期间切换窗口或取消，不发送模型请求；辅助进程结束，下一次可用 | 待验证 |
| 两组快捷键 | 修改/禁用/重启选词键，唤起键不受影响；重复键验证失败，系统占用保留原绑定 | 待验证 |
| 模型取消/错误 | 选词后长流式请求可取消，401/429/超时仍正确反馈，可手动重试 | 待验证 |

该项 Windows 原生闭环验收通过后，才进入“区域截图 → OCR → 编辑识别文字 → 翻译”。托盘在其后。未支持的特定目标应记录为兼容性限制，不伪装为成功。
